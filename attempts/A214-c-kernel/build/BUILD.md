## Rebuild (one command)

    sh attempts/A214-c-kernel/code/build214.sh          # or: powershell -File attempts\A214-c-kernel\code\build214.ps1

which runs

    clang -O2 -shared -nostdlib -Wl,-noentry -ffp-contract=off -fno-fast-math -Wall -Wextra -std=c11 \
          -o build/ckernel214.dll code/ckernel214.c

and rewrites `ckernel214.dll.sha256`.  Then `python tests/all214.py` (the differential tests) must print
`ALL214 rc=0`.  `CLANG=/path/to/clang sh code/build214.sh` builds with another compiler.

* `-ffp-contract=off -fno-fast-math` are REQUIRED: the float filter's error bound assumes one rounding per
  operation, so FMA contraction and reassociation must be off.
* `-nostdlib -Wl,-noentry` because this machine has clang but no MSVC CRT import libraries (`libcmt.lib`); the
  kernel needs no CRT and defines the two symbols the code generator emits (`_fltused`, `memset`) itself.
* The build is NOT byte-reproducible (the PE header carries a timestamp and the linker embeds the output path), so
  a rebuilt DLL has a different sha256 from the committed one; the recorded hash pins the artifact that was tested.
  A fresh build of the same source passes `tests/diff214.py` identically (checked 2026-09-14 with `A214_DLL=` on a
  temporary build).

## If the DLL is missing, stale, or the machine differs

Nothing breaks: `ckernel214.AVAILABLE` is False (load failure, version mismatch, struct-size mismatch or a failed
`a214_self_test` all land there), `install()` becomes a no-op, and A213's Python-int path runs exactly as before.
`A214_CKERNEL=0` forces that too.
