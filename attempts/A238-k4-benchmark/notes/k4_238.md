# A238 — the k5 toolkit on the Trump-parent protected classes (k4_11, k3_02)

PI, 2026-09-16 10:30: *"the k4- classes that are parents of Trump shouldn't be able to get that close to Trump, since
a bunch of the geo tests will kill them when they try to press the fifth simple square into place."*

A100 priced those classes with the case-LP: ≈ 560 s of LP+certification per level-1 cover cell, 0.38 first-pass kill
rate on k4_11, 3,500–4,200 CPU-h per class, 4,247–4,578 CPU-h for the tier. This attempt re-prices the SAME nodes —
same hypothesis, same boxes — with the geometry the k5 frontier uses today.

## 0. What a node is, and what its certificate says

`code/load238.py` turns a protected class into a page for the k5 runner. The record is exactly the format
`geo178.load_record` reads, so every downstream library (A203 Stage 0 + CSP, A204/A205 clips, A206 Rule NS, A207
basin clip, A208 no-room, A210 rule CC, A211's coarse tree, A212's gate) consumes it unchanged:

* **pins** = the class's k_S slots as upright boxes of half-width δ_pin/√2 with exact core a = 1/2 − δ_pin,
  δ_pin = 2·10⁻² — A84's slack pin cores at A100's operating point, so the hypothesis is A100's verbatim;
* **H** = one conditioned free square: either a cell of A100/A84's level-1 cover of the interior zone
  ([1.1, s0−1.1]² × [0°, 90°) on a 12 × 12 × 8 grid, nid `<cls>_c0_Y<i>`), or the whole zone (nid `<cls>_root`,
  the A84-P1 node whose NO child is A100's `p1_interior` certificate);
* **budget** = 11 − k_S − 1 anonymous free squares.

**The hypothesis, stated on every certificate** (`hypothesis` on the doc, and in the verifier clause):

> **M_S(m) & YES(H).** P is a packing of eleven unit squares in [0, m]², m ∈ [ŝ − δ_basin(S), s0], with an
> axis-aligned unit square centred at every slot of class S (slack pin cores, δ_pin = 2·10⁻²: Lemma P-TREE §1), and
> some square of the dilate Δ_{s0/m}P other than the k_S pin owners has its (centre, tilt) in H.

A **DEAD** verdict on such a page is therefore the instance of `stratum_kill` for **that class S restricted to H**
(Lemma K1 / Lemma P-TREE (c), obligation **O1** of `docs/proofs/protected_trees.md` §5) — nothing about any other
class. The runs are pad 0 (λ = 1), i.e. statements at s0, exactly like A100's level-1 LP certificates; carrying them
over the window is A100's parametric layer (its L4/L5), not re-done here, and every row is labelled
`s0_only: true`.

## 1. The three rules that make a Trump PARENT different

A protected class with G_S ≠ ∅ is a Trump parent: its pins **are** k_S of Trump's five simple squares. So the class
root *contains* a Trump image, and a kill rule that fired there would be unsound. A212 solved this for trump5; A238
re-applies its three rules to A211's **live** tree (see §2):

1. **the GATE** (A212 §1): every node is tested, before and after its cascade, for an injective assignment of its
   named squares to the squares of a D4 image of ẑ embedded at s0. A gated node is never killed; a rule or cascade
   claiming DEAD there records `gate_conflict` and the node stays ALIVE. **This is the measurement instrument**: it
   splits the tree into the branch that still holds Trump and the branches that do not, and the PI's question is
   exactly how fast the second kind dies.
2. **the TUBE LEAF**, here **Lemma TUBE-LEAF/S** (`code/tube238.py`), the class form of A212 §2. A212's leaf uses
   trump5's SCALE ray; a parent class uses its own direction slot(I_g) — A84 §4's swept certificates
   `certs/tube_I_<I>_landing_T*_rc1o625_rt21o10000.json` (k4_11: I = {0,2,3,5}, T = 0.0448; k3_02: I = {0,1,3},
   T = 0.0448). The pins are **exempt from the radius**: M_S(m) puts the pin squares exactly on slots_S(m), which is
   the tube direction's *pinned* coordinate (w = 0, Lemma P-TREE Step 4), so the clause on a pin is "the assigned
   image square is upright and sits on this pin's slot" (exact, tolerance 10⁻⁹) and the slack pin box — a relaxation
   used only for the s0 branching and the (K) certificates — never enters. Only the N = 11 − k_S free squares must
   lie inside (r_c′, r_θ) = (1.5992·10⁻³, 2.1·10⁻³). A TRUMP-TUBE leaf is a **(D) discharge**, not a kill.
3. **Rule SNAP at the gated leaf** (A224, `docs/proofs/snap_rule.md`). This is the PI's sentence made operational.
   For k4_11 the class pins are BL(0,0), BL(0,1), BR(0,0), TR(0,0) and the **fifth** simple square of Trump sits at
   BL(1,0) — which Theorem FC does *not* list as a forced cell of k4_11 precisely because its extension class is
   trump5, the one k5 class that is still open. So when a near-simple role with no second meeter snaps into a slot,
   the target stratum decides: **trump5 ⇒ HAND-OFF** (the branch leaves this class's tree and joins trump5's queue),
   any other k5 class ⇒ **DEAD by Lemma K1** (its scoreboard row is FULL over the whole window). Tree238 runs SNAP
   *first* at a gated fully named leaf as well as at the ungated ones.

A212's **aligned split** (§3) is deliberately not re-applied: A212 §6 measured that a gated node needs ≈ 36 aligned
cuts to fit the tube box and that its near-Trump siblings do not die inside a wall. A gated fully named leaf is
instead left ALIVE with its tube **excess** recorded (`tube` on the node record) — "tube-pending: the (D) discharge
needs the contraction lever (A60's LP ladder / A83's basin clip), not more branching".

## 2. Why not A212's own runner

`attempts/A212-trump5-tree/code/` carries **frozen copies** of `tree211`, `tree206`, `tree209`, `coarse211`,
`leaves211`, `poly204`, `load211`, `stage209`, `run211` from 2026-09-11 — i.e. from before A220 (exact-first /
no-room inherit), A221 (pocket cover), A224 (SNAP) and A230 (EPS). Benchmarking on them would price a toolkit nobody
uses. `code/tree238.py` therefore subclasses **A211's live `Tree211`** — the very class the five running k5 frontier
workers execute — and re-applies A212's gate/tube/snap rules on top; `code/path238.py` enforces the import order
`[A238, A211, …, A212]` and asserts it at start-up (`path238.check()`), so only `trump212` ever comes from A212.
Nothing in A100, A84, A211, A212 or A224 is edited; all are imported read-only, and A238 writes only its own
`certs/`, `results/`, `logs/` and `docs/residue_map/campaigns/A238-k4-benchmark/`.

## 3. How to read the numbers

`results/bench238.jsonl` has one row per node: verdict, tree seconds, stage-0 seconds, `priced_seconds` (the honest
per-cell cost = stage 0 + tree), node count, depth, `kills_by_rule`, the gate census, the tube census, the SNAP
census with its hand-off targets, and — for the head-to-head cells — **A100's own row on the same box**
(`a100`: verdict, `lp_s`, `cert_s`, τ, η). `results/bench238.md` (regenerated by `code/report238.py`) is the
comparison table and the tier extrapolation; `results/bench238_summary.json` the same as data.

The queues (`code/queue_<cls>.txt`, built by `code/queue238.py`) are ordered so the comparison is exact:
the root, then **every level-1 cover cell A100 actually priced by LP**, then the cells that hold an image square
(the gate/tube evidence), then a stratified extrapolation set in A84's own nearest/median/farthest-by-`ghost` order.
